Open http://localhost:5173/#/login in an Incognito/InPrivate window. Use the retained administrator or a real assigned employee account. Test a synthetic workbook instead of modifying business records. Open Files, then Verify file password: the password box should have a caret immediately, accept letters, digits, symbols, spaces, paste, Backspace and arrow-key edits without losing focus. Check new/existing cell-lock passwords and offline-download confirmation fields too. Password limits and actual verification rules are unchanged. Escape and Cancel still work, and a busy verification cannot be dismissed through Escape.

The fix is in the shared FileModal focus lifecycle: changes to an inline onClose callback update a ref instead of restarting focus setup on every keystroke. This also protects other FileModal text fields and communication dialogs. Login/reset/user-management password fields were audited separately; they do not use that focus lifecycle.

For the full local native editor, Docker's engine and the ONLYOFFICE container must run on this PC. Backend/frontend alone work in lite mode, with native editing unavailable. Docker Desktop does not need to stay open on employee PCs after deployment: the NAS runs ONLYOFFICE using Container Manager. See backend deploy/onlyoffice/DS1525-HANDOFF.md.

The owner authorized GitHub publication on 6 November 2026. Deploy only with the existing NAS data mounts and private production environment; do not import local demo data.

Verified document passwords now persist encrypted in the database. Restart the backend in IntelliJ after this upgrade, verify a synthetic document once, save, then restart and reopen it to confirm EAC remembers verification. The private local APP_FILES_PASSWORD_KEY is already prepared and must remain stable; production uses its own private key and V18 migration. A new Incognito native editor can still ask for the original file-opening password: remembering EAC verification does not remove the workbook’s encryption.

Saved-access sharing: apply and save the workbook's sheet assignments and cell locks, open Share, select the employee, leave “Use saved file access” selected, then choose “Send with saved access”. The server derives Viewer/Editor from the employee's saved sheet assignments; it does not grant Manager. Pending sheet changes or a workbook with no accessible assigned sheets are rejected. Existing document bytes, cell locks, sheet policy and opening password are unchanged. For files without a sheet policy, existing direct permission is retained, or a new recipient gets Viewer. New recipients default to downloads blocked; existing download choices remain visible and adjustable. Database password records never expire; the short-lived plaintext cache transparently reloads the encrypted record.

Employee work review: share a synthetic file with an employee as Editor, sign in as that employee, edit and save it, then select Send back to owner. In ONLYOFFICE this first requests a checkpoint and opens the return form after a newer saved version is confirmed. Describe the sections changed and submit. The owner opens Files → Employee work review → Returned work to see the employee, submitted version, notes and review status, then uses Version history to inspect that numbered revision and Mark reviewed when finished. Open document shows the latest shared version, which may be newer than the submission. Files sent to employees lists the owner's direct file/folder shares, including their access and expiry. Returns do not duplicate documents or change sheet/download permissions; duplicate submissions of the same employee/version reuse the receipt. Viewers, revoked recipients, stale versions and unverified encrypted saves cannot submit work. Inherited folder editing can return child documents. Return receipts are removed when the file is permanently purged. Each owner can see only their own review list.
